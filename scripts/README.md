# Build Scripts

This directory contains the build, pre-render, deploy, and maintenance scripts for the project.

## Overview

| Script | Command | When it runs |
| --- | --- | --- |
| `generate-sitemap.ts` | `pnpm sitemap:gen` | `prebuild` |
| `generate-feed.ts` | `pnpm feed:gen` | `prebuild` |
| `generate-og-images.ts` | `pnpm og:gen` | `prebuild` |
| `vite-plugin-critical-css.ts` | (Vite plugin) | `vite build` |
| `generate-route-html.ts` | `pnpm route-html:gen` | `postbuild` |
| `prerender.ts` | `pnpm prerender` | `postbuild`, after `pnpm build:ssr` |
| `lighthouse-budget.ts` | `pnpm lighthouse:budget` | CI (`lighthouse.yml`), after a build |
| `deploy.ts` | `pnpm deploy:hostinger` | `deploy.yml` on `v*` tags, or locally |
| `deploy-status.sh` | `./scripts/deploy-status.sh` | manually |
| `indexnow-ping.ts` | `pnpm indexnow:ping` | manually, after a deploy with new content |
| `optimize-images.ts` | `pnpm optimize:images` | manually, when profile images change |
| `harden-github-repo.sh` | `./scripts/harden-github-repo.sh` | manually, to reapply GitHub repository settings |

## Scripts

### `optimize-images.ts`

Generates optimized versions of images in multiple formats and sizes.

**Usage:**

```bash
pnpm optimize:images
```

**What it does:**

- Converts images to WebP and AVIF formats
- Creates responsive versions (252px, 512px, 1024px)
- Optimizes JPEG compression
- Provides detailed size comparison reports

**Requirements:**

- `sharp` package (installed as dev dependency)

### `vite-plugin-critical-css.ts`

Custom Vite plugin for extracting and inlining critical CSS.

**What it does:**

- Extracts above-the-fold CSS during build
- Inlines critical CSS in HTML `<head>`
- Preloads non-critical CSS
- Reduces render-blocking resources

**Configuration:**
See `vite.config.ts` for plugin options.

### `generate-sitemap.ts`

Generates `public/sitemap.xml` from the main routes, `FEATURED_REPOSITORIES`, and `blogPosts`. Runs before each production build. See [docs/routes-and-sitemap.md](../docs/routes-and-sitemap.md).

### `generate-feed.ts`

Generates the RSS 2.0 feed at `public/feed.xml` from `blogPosts`. Runs before each production build.

### `generate-og-images.ts`

Renders a 1200×630 Open Graph image per route (home, pages, projects, and posts) with `sharp`, into `public/images/og/` (gitignored). Runs before each production build.

### `generate-route-html.ts`

Creates `dist/<route>/index.html` with the correct `<title>`, description, canonical, and `og:*` tags for every known route. Avoids soft 404s and wrong canonicals in Search Console.

### `prerender.ts`

Injects the HTML rendered by the SSR build (`vite.config.ssr.ts`) into the `#root` of each route generated by `generate-route-html.ts`, and writes `app-shell.html` as the fallback for runtime-only routes.

### `lighthouse-budget.ts`

Starts `vite preview`, audits `/`, `/blog/`, and `/services/` with Lighthouse, and exits with code 1 when a category score or metric (LCP, CLS, TBT) breaks the budget. Analytics requests are blocked during the audit.

```bash
pnpm build && pnpm lighthouse:budget
```

Chrome is launched with `RenderDocument` disabled: since `chrome-launcher` 1.2.3 it is no longer in the default flags, and without it Lighthouse fails with `LanternError: rootNode not found`.

### `indexnow-ping.ts`

Notifies IndexNow search engines (Bing, Yandex, Naver, Seznam) about the site URLs. Requires the public key file in `public/` to be deployed first.

### `harden-github-repo.sh`

Reapplies the GitHub repository settings (squash-only merges, auto-merge, branch deletion, and related options) through `gh api`.

### `deploy-status.sh`

Checks the deployment status of the website.

**Usage:**

```bash
./scripts/deploy-status.sh
```

### `deploy.ts`

Builds the app and deploys `dist/` to Hostinger over SSH with a remote backup.

**Usage:**

```bash
pnpm deploy:hostinger
pnpm deploy:hostinger -- --dry-run
pnpm deploy:hostinger -- --skip-build
```

**What it does:**

- Loads deploy credentials from `.env.deploy` or `.env.deploy.local`
- Creates a timestamped backup of the remote web root
- Synchronizes `dist/` with `rsync`
- Verifies the deployed homepage, `robots.txt`, and `sitemap.xml`

For Hostinger domain hosting, `DEPLOY_REMOTE_DIR` should usually point to:
`/home/USER/domains/DOMAIN/public_html`

## Performance Optimization Workflow

1. **Optimize Images**

   ```bash
   pnpm optimize:images
   ```

2. **Build for Production**

   ```bash
   pnpm build
   ```

   This automatically:
   - Generates the sitemap, RSS feed, and OG images
   - Inlines critical CSS
   - Bundles and minifies code
   - Compresses assets (gzip + brotli)
   - Pre-renders every known route

3. **Preview Locally**

   ```bash
   pnpm preview
   ```

4. **Deploy & Test**
   - Deploy to production
   - Run PageSpeed Insights
   - Verify improvements

## Maintenance

### Adding New Images

When adding new profile images or hero images:

1. Place the original high-resolution image in `public/images/profile/`
2. Update `scripts/optimize-images.ts` if needed
3. Run `pnpm optimize:images`
4. Update image references in components

### Updating Critical CSS

To modify what CSS is considered critical:

1. Edit the inline styles in `index.html`
2. Adjust Beasties settings in `vite-plugin-critical-css.ts`
3. Rebuild and test

## Dependencies

- **sharp**: Image processing library
- **beasties**: Critical CSS extraction
- **lighthouse** and **chrome-launcher**: performance budget
- **tsx**: TypeScript execution

All dependencies are installed as dev dependencies.
